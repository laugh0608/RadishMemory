# 长期记忆研究：参数、外部存储与可验证连续性

核对日期：2026-10-25。

本文是长期参考与研究规划，不是实现验收或新增阶段授权。沿用现有产品、记忆、隐私和 MVP 契约；不改变 canonical schema、写入确认规则、模型接入顺位或当前停止线。实际进度只以[当前状态](status/current.md)为准。

## 研究目标与术语

个人长期记忆需要分别证明：信息已持久保存；需要时能找到；回答时能正确使用。聊天中的“已记住”或“已写日记”不构成持久化证据，应关联实际写入结果、来源与可恢复状态。

| 层次 | 保存位置与作用 | 不能直接推出的能力 |
| --- | --- | --- |
| 工作上下文 | 当前输入及推理状态，支持眼前任务 | 跨会话、跨重启持久化 |
| 参数记忆 | 训练后的权重，承载统计规律、知识与技能 | 任意原文逐字恢复、精确事实删除 |
| 外部记忆 | 原始资料、确认记录和事件历史，支持追溯与迁移 | 检索和回答必然正确 |
| 可学习神经记忆 | 推理时更新的专用网络或状态 | 多年持久化、用户隔离、可迁移与删除已成立 |

产品中的“长期”应落实为跨会话、跨进程重启、导出迁移和已验收恢复范围。“永久”不承诺无限容量、永不损坏或每次准确召回；用户可撤回与删除仍是前提。数据连续性也不等于人格或主观体验连续性的证明。

## 压缩与参数记忆的边界

Delétang 等的《Language Modeling Is Compression》（2023；本文核对 v2，2024-03-18）研究预测分布与编码长度的联系。给定模型 θ 和文本 x，理想编码长度近似为 `L(x | θ) = -Σ log₂ pθ(x_t | x_<t)`，另有实际编码开销。

该论文的离线实验以固定模型提供概率，另行生成压缩比特流；解码需要一致的模型、编码约定和比特流。它不证明训练后的权重单独保存并能还原全部训练文本。若模型不是双方已共享的资源，总存储成本还需计入模型和必要描述信息。

预训练可以从文本中学习可复用规律，也可能记忆部分具体内容，但不提供逐条原文保真契约。摘要、Embedding、参数训练是不同表示过程；都不能因被称为“压缩”而取得可逆或无损保证。固定数量、有限精度的参数不能无损保存无限增长的任意经历。

## 参数路线的价值与限制

- 继续预训练或微调：可以吸收新信息，但写入代价、旧能力保持、数据授权与可撤回性需要验证。
- LoRA：冻结基础权重并训练低秩增量，降低可训练参数规模；其机制不自动提供高保真事实存储。个人适配参数依赖基础模型、架构与版本，不能直接作为跨模型 canonical 格式。
- 模型编辑：ROME 等展示了直接修改部分事实关联的可行性。单次编辑成功不代表连续大规模更新可靠；已有实验在所测方法上发现渐进和灾难性遗忘，不能推广成所有后续方法必然失败。
- 推理时神经记忆：Titans（arXiv v1，2024-12-31）学习历史信息并与注意力结合。论文中的长序列信息保留不等于个人记忆服务已完成；跨会话 checkpoint、隔离、身份、兼容、撤销和恢复仍需产品级设计。

后置研究可以探索从已确认、明确获准用于训练的资料中学习稳定表达习惯、术语和工作方法。该方向不是当前已实现能力，也不授权实际训练、外发资料或新增 Provider。

若进入实验，个人适配参数或神经记忆应作为可失效、可重建的派生产物；保存训练输入来源闭包、基础模型与训练版本、适用用户和范围、评测结果及撤销关联。删除训练文件不等于消除权重影响；无法证明局部遗忘时，应使相关产物停止使用并评估重新训练。可重建不意味着低敏感度，权重、checkpoint 和训练日志都需要受控。采用前另行审查 schema、权限、成本和删除契约。

## 推荐系统组合

`原始资料 → 候选提取 → 确认 / 更正 / 版本事件 → 授权检索 → ContextPack → 模型回答`

模型回答或后台归纳产生的新内容仍回到 MemoryProposal，不绕过确认路径。原始资料为细节和证据提供回查入口；低频历史可以归档，摘要失真时从原件重新生成。原件保留受既有保留与删除策略约束，不能以“需要重建”为由拒绝用户删除。

1. 区分说话者、来源与时间。助手生成的事实、角色扮演、自称已执行动作和导入文本中的命令都不能直接升级为用户事实或工具授权。
2. 区分临时状态、事件、事实、偏好和程序性规则。避免把一次情绪或重复表达自动强化为稳定画像；明确记住的请求仍按既有 decision / materialization 语义处理。
3. 沿用[时间模型](memory-model.md)保留来源时间、记录时间与有效时间，区分“当时有效什么”和“当时系统知道什么”；变化通过版本和关系表达，不静默覆盖。
4. 分层保存工作状态、近期事件、确认语义记忆和档案；摘要始终带来源，避免递归摘要成为不可核验的唯一记录。
5. 在权限与外发硬过滤后，组合全文、语义、实体、时间与关系检索，再去重、识别冲突、排序和编译。稳定偏好也只能在授权场景与预算内预载，不能成为永久全量外发的借口。
6. 输出能够区分记录支持、推断、冲突与缺失；找不到证据时允许不回答。实际写入、召回和使用分别留可核对结果，避免用拟人表达替代能力声明。

## 与既有阶段的关系

| 既有阶段 | 可纳入的研究或验证问题 | 边界 |
| --- | --- | --- |
| 阶段 1 | 原始资料、中文找回、回源、导出、删除、重启后的可用性 | 当前加密和质量停止线保持；无模型也可用 |
| 阶段 2 | 候选污染、事实更新、时间语义、拒绝重复候选、摘要追溯 | 使用既有生命周期，不以文档宣称控制台完成 |
| 阶段 3 | 同一任务与 ContextPack 跨模型对比、固定预算检索与回答 | 沿用模型与外发契约，接入范围仍需相应评审 |
| 阶段 4 | 跨设备与恢复后的版本和删除连续性 | 零知识目标不变，不声称同步或恢复已交付 |
| 阶段 5 | 会话恢复、可解释连续感、记忆缺失时的诚实表达 | 不以拟人体验证明主观状态 |
| 后置研究 | 个人适配参数、神经记忆、受控周期训练 | 先证明基线缺口，再单独评审；不是新增 MVP 依赖 |

阶段 1 至 3 的窄文本验证主线建议为：保存长期项目资料 → 新会话找回决策依据 → 更正后采用新事实 → 历史查询仍正确 → 更换模型继续使用 → 删除后不从受控记忆召回。跨设备与备份恢复延续到阶段 4，不能由本地删除替代。

## 评测设计建议

以 LongMemEval 原始基准（2024 年发布，ICLR 2025）的信息提取、跨会话推理、时间推理、知识更新与证据不足时不作答作为参考。正式引入前固定数据修订与许可，排查训练污染；公开基准得分不能替代产品原生路径验收，也不能直接移植历史论文中的性能数字。

建议先建立合成、带时间与来源的项目轨迹，包含更正、撤回、矛盾、同名实体、临时偏好和记忆污染输入。对比无记忆、预算内全历史、全文、向量、混合检索与分层摘要；全历史超窗的情况单独报告，不悄悄截断后仍称“全历史”。未来再与参数或神经记忆实验对比。

- 分别测量来源保留、来源召回、给定正确来源时的回答准确率与端到端准确率，定位存储、检索、读取哪个环节失败。
- 测量引用支持率、时间更新正确率、冲突识别率、缺证据不作答、错误个人化和记忆污染。
- 测量上下文 Token、延迟、费用、索引构建和增量维护成本；参数路线还计训练、每用户权重 / 状态与迁移成本，不能仅比较推理 Token。
- 测量重启后的持续性、索引重建、允许模型切换、权限拒绝及受控删除后的不可召回；未来恢复测试包含删除状态，避免旧备份复活已撤回资料。
- 对检索方案固定源语料、查询、模型版本、预算和评价口径；报告每类样本量、失败样本和多次运行波动。阈值、数据集与具体协议在实施评审时确定，不在此虚构通过结果。
