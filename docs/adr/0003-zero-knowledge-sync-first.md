# ADR 0003：首个同步采用零知识服务

日期：2026-08-22

状态：Accepted

## 背景

RadishMemory 的完整 MVP 要通过用户自部署服务把资料、记忆状态和删除状态安全同步到第二台设备。这个目标至少有两种不同信任前提：可信私有服务器可以解密并执行语义计算；零知识同步服务只中继密文，由受信设备承担解密、索引和记忆计算。二者会改变明文位置、密钥归属、恢复方式、服务端能力和失陷影响，不能在实现中作为普通配置细节临时决定。

M0 仍是单用户、单设备、无网络的本地闭环。本 ADR 不把同步加入 M0，也不冻结具体密码算法、线协议或存储产品；它冻结后续首个多设备同步实现必须满足的信任边界。

## 决策

首个多设备同步实现采用模式 B：零知识同步服务。默认自部署服务端不持有用户内容解密能力，只保存密文对象、加密操作日志、加密密钥封装和完成路由、完整性核对、配额及删除传播所必需的最小元数据。

可信私有服务器模式不进入首个同步批次。未来若支持，必须作为名称、配置、迁移和安全声明均独立的信任模式另行决策，不得从零知识模式静默降级。

### 信任边界

零知识只描述服务端无法解密用户内容，不代表服务端可信、不可观察或系统已经端到端安全：

- 用户仍信任受权设备及其本地操作系统、RadishMemory 客户端和密码学实现处理明文；
- 服务端可以观察被明确允许的账号或租户标识、设备公开身份、对象和操作的密文大小、时序、频率、协议版本、配额及网络端点等元数据；
- 服务端仍可能拒绝服务、延迟、遗漏、重放或回滚同步数据，客户端必须检测能够检测的完整性、版本和重放异常并显式失败；
- 设备失陷、用户导出、云端 Provider 外发和已解密历史数据不因服务端零知识而自动安全；
- 备份中的密文可能继续存在，删除完成必须按实际副本、设备和保留期报告。

实现前必须枚举服务端可见元数据、用途和保留期。未枚举字段不得以日志、索引、诊断或“便于查询”为由上传。

### 职责分配

| 能力 | 受信设备 | 零知识同步服务 |
| --- | --- | --- |
| 根密钥生成与保管 | 是 | 否 |
| 内容与操作载荷加密、解密 | 是 | 否 |
| 解析、全文 / 向量索引、检索 | 是 | 否 |
| MemoryProposal、状态与冲突处理 | 是 | 否 |
| ContextPack 与模型外发策略 | 是 | 否 |
| 密文对象与加密操作日志中继 | 产生、验证并应用 | 保存、排序和传输 |
| 设备公开身份与授权封装 | 发起、批准并验证 | 保存和路由 |
| 删除传播 | 发起并核验各端状态 | 删除服务端副本并返回真实结果 |

服务端不得持久化或记录以下内容：

- 原始资料、片段、记忆、摘要、Embedding 或 ContextPack 明文；
- 根密钥、未包装内容密钥、恢复秘密或可独立解密用户内容的凭据；
- 服务端可查询的语义索引、实体图、用户画像或明文操作载荷；
- Provider API Key、模型请求正文或未经枚举的诊断数据。

传输加密不能替代对象和操作载荷的客户端加密。密码算法、密钥派生、密钥层级、nonce、签名、设备授权证明和线协议必须使用成熟实现并经过独立设计评审；本 ADR 不授权自行发明密码协议。

### 设备、密钥与恢复

- 每台设备具有独立身份和可撤销授权；服务端只持有验证与路由所需的公开身份或不透明授权材料。
- 新设备获得解密能力必须由现有受权设备或用户持有的恢复材料批准，服务端账号重置不能单独恢复内容解密能力。
- 设备撤销必须阻止其继续获取后续同步数据，并把它排除在未来数据密钥分发之外；需要时执行未来数据密钥轮换。
- 撤销不能声称擦除设备已经解密、缓存或导出的历史明文。
- 恢复流程必须明确恢复材料丢失的后果，并以真实备份恢复和防回滚验证证明可用，不能用默认成功或服务端万能恢复掩盖密钥丢失。

具体密钥层级和恢复协议在同步实现前另行冻结，并更新威胁模型。

### 同步与删除语义

- 同步以加密不可变对象和加密追加操作日志为基线；服务端数据库不是记忆 canonical truth。
- 客户端应用操作前验证对象摘要、协议版本、因果或版本约束以及幂等标识；无效、重复、缺失或回滚输入不得静默形成当前状态。
- 并发记忆变更保留版本和冲突，不以服务端最后写入时间静默覆盖。
- 删除通过可同步的删除意图和状态传播；服务端只报告其实际删除的在线副本、排队任务和备份到期情况。
- 离线设备、未处理副本或未到期备份存在时，`DeletionEvidence` 必须保持 pending，而不是报告完全删除。

精确的 `SyncOperation`、对象 envelope、设备身份、冲突和确认协议仍是实现前待冻结契约。

### 可选可信计算节点

家庭服务器或常开设备可以在后续作为可信计算节点显式注册，但不属于首个同步批次。它必须拥有独立设备身份、用户可见的能力与 namespace 范围、单独密钥授权、审计和撤销路径。

一旦用户授予可信计算节点解密能力，该节点就在相应范围内处理明文；产品必须把它与零知识同步服务分开显示和说明。不得默认启用、借用服务端部署身份自动授权，也不得因后台任务失败而回退到服务端明文计算。

## 验收门槛

首个同步实现至少用合成数据和受控测试证明：

1. 检查服务端存储、日志和网络载荷时，不出现内容明文、未包装内容密钥、语义索引或 ContextPack；可见元数据与已冻结清单一致。
2. 服务端不可用时，本地采集、浏览、索引和检索继续工作。
3. 经授权的第二台设备可以恢复对象、记忆版本、冲突和删除状态，并验证内容完整性。
4. 未获授权或已撤销设备不能获得未来数据的解密能力；测试同时准确声明历史明文无法远程收回。
5. 篡改、重放、缺失、未知协议版本和不可安全合并的并发输入产生显式错误或冲突，不静默接受或回滚。
6. 服务端副本、离线设备和备份的删除状态分别可见，未完成节点不会被宣称为已清除。
7. 恢复材料、真实恢复步骤和不可恢复情形均被验证和说明。

完成这些门槛前，仓库和产品只能把零知识同步描述为“已接受的目标信任模式”，不能声明零知识服务端、端到端加密同步或生产可用已经实现。

## 被拒绝的方案

### 首发可信私有服务器

它能更快提供服务端搜索和后台任务，但服务端失陷会暴露集中明文，并会先固化与长期隐私方向相反的密钥和索引边界。它可以成为未来独立模式，不作为首发基线。

### 首发同时实现两种模式

同时维护两套密钥、索引、恢复和声明路径会扩大首批验证面，也容易产生隐式降级。没有真实需求和迁移测试前不承担这项复杂度。

### 默认可信计算节点

常开节点能够承载后台语义任务，但默认授予解密能力会模糊服务端零知识承诺。该能力必须后置并显式授权。

## 后果

收益：服务端失陷不会直接暴露内容明文；本地计算和数据所有权边界一致；后续增加服务端部署或更换存储不会要求把语义索引变成服务端真相；安全声明有可测试的边界。

代价：设备注册、密钥分发、恢复、撤销、冲突、防回滚、客户端索引和多端删除显著复杂；纯 Web、无可信设备后台任务和服务端统一搜索不能直接成立；首个同步批次需要独立密码协议评审和更强故障测试。

## 后续决策

在进入同步实现前，仍须冻结：威胁与元数据清单、密钥层级和恢复协议、`SyncOperation` 与对象 envelope、设备授权与撤销协议、冲突 / 防回滚语义、删除及备份证据，以及相应的合成 fixture 和故障矩阵。
