# 阶段 1 本地资料库质量验收计划

状态：计划，部分实现已推进，尚未完成完整场景验收。依据：[2026-09-05 审阅](../implementation/2026-09-05-project-review.md)。本文件补充 production 入口和用户体验证据，不替换 M0 fixture、`P1-F01` 至 `P1-F18`、`P1-HF01` 至 `P1-HF12` 或 Source Vault 验收，不新增 canonical schema、fixture operation 或另一套 application API。

具体批次顺位、停止线与授权范围以[当前状态](../status/current.md)为准。Q01 至 Q08 是后续工作引用的验收编号，不是已经启用的 CI gate；实现与指标阈值应随对应修复或设计评审确定。

## 入口与数据

使用纯合成 `.txt` / `.md`、独立临时资料库、固定生成 seed 和显式授权根。业务操作通过 production application service；涉及 controller、UI 可到达性或系统 picker 时追加对应宿主验证。需要损坏注入时，只操作任务专用合成数据库，不访问用户资料库。

测试 oracle 必须与实现输出分离。不得将预期命中塞入 production query，不得只通过 runner 专用词项扩展或内存历史投影宣称产品能力成立。文件重启、默认 production features 与 opt-in 测试 features 的证据分别记录。

## 证据与指标

每次记录基线 commit、构建 features、平台、合成生成器 / seed、对象数量、大小和版本分布、实际入口、操作结果及未覆盖项。日志只保留最小计数、状态和耗时，不复制正文、路径、数据库或密钥。

检索质量除 Recall@k 外还应观察无答案误召回、高相似干扰、引用定位和更新后旧版本排除。性能指标先建立可重复基线，再由对应评审确定预算；优化不能省略权限拒绝、完整性、时间或删除验证。

后续记忆控制台增加候选接受 / 拒绝率、重复候选率、每次确认耗时及每周维护时间，用于衡量用户负担。当前未引入真实用户研究、telemetry、模型调用或外发数据采集。

关闭某个审阅项时，必须在当前状态关联实际修复提交和对应证据；没有实现、未运行、环境受阻和已运行失败应分别报告。文档、静态检查或健康库上的 rebuild 成功不能替代受损库启动后的维护入口验证。
