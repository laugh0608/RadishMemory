# RadishMemory 产品范围

## 一句话定义

RadishMemory 是一个用户拥有、模型无关、隐私优先的个人长期记忆与上下文系统，使用户可以把持续积累的资料安全地提供给不同 AI 使用，同时保持来源、时间、权限、纠错和遗忘能力。

## 要解决的问题

今天的 AI 主要依赖有限上下文、单次会话历史或平台私有记忆，存在以下长期问题：

- 上下文窗口是临时工作内存，不是可靠的长期记忆；
- 不同模型和应用之间的记忆相互割裂；
- 文件、灵感、对话、偏好和经历难以形成统一且可追溯的个人上下文；
- 仅靠向量相似度无法可靠处理时间变化、人物关系、矛盾事实和用户习惯；
- 用户难以知道模型为什么记住、为什么召回、把什么发送给了云端；
- 托管式个人资料库会形成长期隐私和迁移风险。

## 核心价值

RadishMemory 的核心不是保存更多文本，而是提供四种长期能力：

1. **持续采集**：随手保存短语、灵感、文件、网页、图片、音频、对话和应用事件。
2. **可靠记忆**：把原始资料转换为有来源、有时间、有状态的事实、经历、偏好和程序性记忆。
3. **上下文编译**：根据任务、权限、时间和 Token 预算，为任意模型构建有限的 `ContextPack`。
4. **用户主权**：用户控制部署、密钥、模型外发、纠错、迁移、备份和遗忘。

## 目标用户

首要用户是愿意管理自己数字资料、经常使用多个 AI 工具，并对长期记忆和隐私有明确需求的个人用户。早期产品按单用户设计，但数据模型不应阻断未来家庭或小团队的受控共享。

## 首个价值验证场景

早期验证聚焦一个长期项目：用户保存资料，之后找回依据，确认并更正关键事实，再为当前 AI 任务提供有限、可追溯的上下文。它用于检验现有来源、时间、确认与权限设计是否解决日常问题，不取消完整产品范围，也不自动提前模型或同步实现。

首个体验应能回答“保存后是否找得到”“引用是否能回到具体内容”“更正后是否还会误用旧事实”“用户维护这些记忆要花多少时间”。资料数量、插件数量或候选生成量不能代替这些结果。具体阶段以[MVP 路线图](mvp-roadmap.md)为准。

## 产品体验

RadishMemory 是一个项目，内部可以提供多种体验：

- 快速收件箱：一句话、剪贴板、分享菜单、文件拖入和语音速记；
- 个人资料库：按人物、项目、时间、主题和来源浏览；
- 问答与研究：跨资料检索、总结、比较并引用来源；
- 个人伴侣：使用同一记忆核心提供连续对话、偏好适配和虚拟形象；
- AI 工具接口：通过本地 API、MCP 或稳定协议向其它应用提供受控上下文；
- 记忆控制台：审查候选记忆、冲突、模型外发、同步和删除状态。

个人伴侣不是独立项目，也不拥有第二套记忆；它只是 RadishMemory 的一个产品界面。

## 产品承诺

- 用户能看到每条记忆来自哪里。
- 用户能区分自己明确说过的事实与模型推断。
- 用户能修改、撤回或要求忘记某条记忆。
- 用户能知道本次请求向哪个模型发送了哪些上下文。
- 用户更换模型、Embedding 或服务器时，原始资料与结构化记忆仍可迁移。
- 多端同步服务必须允许用户自行部署。

## 交付与数据可带走的边界

单原件精确导出、完整资产迁移、备份恢复是不同能力。完整迁移需要在其契约中枚举来源、版本、记忆、来源关系、确认决定、策略及必要证据；备份恢复还需要可用解密能力和恢复后完整性验证。不能用“原件可导出”替代“整个记忆资产可迁移”。

用户自部署是产品目标，具体安装、复制、修改和分发授权以根目录 [LICENSE](../LICENSE) 为准。外部试用与发行方案应明确正式渠道、用户获得的授权和维护范围；产品愿景本身不授予这些软件使用权。

## 首个可执行验证边界

首个切片 `M0 Local Memory Loop` 不直接实现完整产品范围，而是在单用户、单设备、本地且无模型的环境中，用合成短文本与 Markdown 验证：原始来源、稳定引用、全文召回、候选确认、时间更正、权限失败关闭和删除证据能够形成闭环。

M0 不接入 PDF、图片、音频、Embedding、云端 Provider、RadishMind 或同步服务。这个窄化边界只控制实施顺序，不取消上述长期产品承诺。具体决策见 [ADR 0002](adr/0002-m0-local-memory-loop.md)。

## 非目标

当前不把 RadishMemory 定义为：

- 从零训练的基础大模型；
- 单一厂商聊天客户端；
- 仅用于笔记编辑的 Notion/Obsidian 替代品；
- 依靠上传所有资料换取便利的托管 SaaS；
- 自动相信所有模型推断的用户画像系统；
- 依靠无限增长 Prompt 保存全部历史的聊天壳；
- 默认拥有无限制工具权限的自主代理；
- 社交网络或公开内容平台。

## 核心成功指标

- **召回正确率**：相关资料能够进入候选集合并支持正确回答。
- **错误个人化率**：系统错误地把推断当偏好或事实的比例。
- **时间一致性**：能正确回答“过去”和“现在”不同状态的问题。
- **来源准确率**：回答引用能够回到真实原始资料。
- **记忆污染率**：错误、重复、低价值和无来源记忆进入确认层的比例。
- **上下文压缩率**：在保持答案质量的前提下，ContextPack 相比完整历史减少的 Token。
- **隐私违规数**：未经授权进入检索或外发的敏感内容必须为零。
- **删除完整性**：正文、索引、缓存、同步副本和备份生命周期均可检查。
- **迁移完整性**：更换模型、索引或服务器后不丢失用户拥有的长期数据。
- **维护负担**：候选确认耗时、重复低价值候选及持续管理记忆所需时间；评测不自动授权真实用户资料或 telemetry。
